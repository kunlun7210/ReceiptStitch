# 智能隐私拼图

一个可添加到 iPhone 主屏幕的网页 App。

使用网址：[智能隐私拼图](https://kunlun7210.github.io/ReceiptStitch/)

项目源码：[kunlun7210/ReceiptStitch](https://github.com/kunlun7210/ReceiptStitch)
在设备本地识别银行卡尾号与可用余额 / 额度，先打马赛克，再将相邻两张照片横向或竖向拼接，最后添加平铺水印。默认横向拼接。

## 使用

1. 在 Safari 打开 https://kunlun7210.github.io/ReceiptStitch/ ，无需账号登录。
2. 点 Safari“分享”→“添加到主屏幕”，保留“作为网页 App 打开”。
3. 可先展开底部“模型信息 ▾”，点“提前下载识别模型”，等待下载完成后再选照片；不提前下载时，首次识别也会自动准备。右上角“？”内的下载按钮与底部共用下载任务和状态，显示实际线路、百分比和 MB，失败可重试。
4. 选取 2 张照片，或批量选择 4、6、8、10 张；每相邻两张组成一组。支持分次添加，最多 20 张。默认按相册返回顺序左右排列；“拼图设置”可改为上下排列。可前移、后移照片，也可交换一组的左右或上下。
5. 等待识别，检查遮挡范围。点“检查左图 / 检查右图”（竖向为“检查上图 / 检查下图”），默认以 1× 按屏幕宽度显示，右侧滑动条可查看底部；可双指拖动，也可切换“移动查看”后单指拖动。需要看全貌时可手动选择“整图”。在“框选遮挡”下单指拖动可补框，双指操作不会添加遮挡。可删除框或撤销补框。
6. 点“保存图片”或“保存全部”，在 iPhone 系统分享面板选择“存储图像”。不支持文件分享时提供下载或长按图片保存。

## 默认水印

- 内容：`机器/收款码办理 详询VX：kunlun7210`
- 字号：50 pt（画布按 96 px/in 换算为 66.67 px）
- 透明度：70%，即文字不透明度 30%；数值越高越浅
- 颜色：浅灰 `#b3b3b3`
- 方式：斜向 30° 平铺，在马赛克与拼接完成之后绘制

水印设置及手动选择的拼接方向保存在当前浏览器；新用户默认横向。“恢复默认水印”只重置水印。照片、OCR 文字和结果不持久化，关闭或重载页面会清空照片。生成的 PNG 不复制源文件的元数据。

字号和透明度均为可拖动滑块，实时显示 pt / 百分比；使用 4px 蓝色线条和 16px 蓝色圆点，没有手动字号输入。

设置按“颜色 → 透明度 → 字号”排列。第一排是红、黑、蓝、浅灰四种常用颜色，以及调色盘按钮；其他颜色收在调色盘的二级菜单，点开显示 6 列 × 5 行固定色板。选中时仅在色块中心显示勾号，不显示外部背景。默认勾选浅灰，无系统颜色器或色号输入。

## 识别与画面

- 支持“银行卡尾号”“银行卡号”“卡号尾号”“尾号”等写法，以及“可用余额”“可用额度”。处理每张图片内全部匹配字段。交易金额和其他内容不主动遮挡。
- 每张图先运行 PP-OCRv6-small，然后根据字段文字及同一行的相对位置确定遮挡区域。识别并非所有银行样式都能保证命中，输出前可手动补框。
- 遮挡区域使用完全不透明、与源内容无关的浅灰色块，并按实际数字的笔画边界收紧，四周保留少量边距。导出后不可从马赛克区域恢复原始像素。
- 手动框选的默认马赛克使用固定 24 像素格子（原 12 像素的 2 倍），不随选区面积或高度增大；格子随图片等比例缩放。检查图片时可选“马赛克 / 纯色 / 涂抹”，即时应用于当前图片全部手动选区；样式会随导出保存，偏好保存在当前浏览器。三种样式均使用与原文无关、完全不透明的浅色像素；涂抹先完全遮挡再添加浅色笔触。
- 横向按同高、竖向按同宽拼接，保留完整画面与长宽比。不自动裁掉状态栏、广告或聊天记录。超大图限制至约 1200 万像素和单边 8192 像素，界面会提示已适配尺寸。两种方向均先遮挡、再拼接，最后在整张成品上加水印。
- OCR 未完成时不能直接导出；可重试，或在两张图中分别手动框选并点“完成检查”后继续。

## 本地与离线

本工具只有静态网页，无图片上传接口、远程识别服务或统计脚本。识别组件默认从 jsDelivr 下载，线路不可用或过慢时自动换源，GitHub Pages 作为备用；图片仅送入当前浏览器的专用 Worker。下载请求不携带图片、识别文字、Cookie 或页面来源。

支持 gzip 解压的浏览器首次下载约 39.2 MB，解压后仍为原来的 79.7 MB 完整组件，并未更换模型或量化。两个模型与 AI 去水印项目相同：9,891,840 字节文字检测模型和 21,319,680 字节文字识别模型，总计 31,211,520 字节。9.9 MB 是其中一个模型的大小。

压缩包和解压后的原始文件均校验 SHA-256，最多同时下载两个组件。下载过程中实时显示百分比、MB 和进度条。jsDelivr 使用固定提交地址；默认域名不可用时尝试其 Fastly / Gcore 线路，然后回退至 Pages。本地预览也默认 jsDelivr，页面显示实际使用的线路；`?source=origin` 仅用于指定当前站点文件进行开发测试。

缓存仍以原始文件地址保存，已有拼图缓存无需重新下载。若同一浏览器曾缓存同一 GitHub Pages 域名下 AI 去水印项目的相同模型和运行组件，会校验后复用；不会读取或修改旧项目图片。若旧模型、WASM 和 Worker 四项都在缓存，只需再下载约 3.5 MB。实际复用量取决于设备保留的缓存。

准备完成后可断网重开并识别、拼图、导出。Safari 清理站点数据、系统回收缓存或首次使用另一个浏览器时需要重新下载。可在“使用说明”中提前准备离线识别。不支持 gzip 解压时使用原始组件；原 WebAssembly 两段合并的兼容路径保留。

## 源码与验证

公开版本号使用两段自然数：v1.1、v1.2、v1.3……，不使用三段版本号。

`dist/` 可直接作为 HTTPS 静态站点部署，不需要构建或运行服务器端程序。模型与运行组件沿用已有截图智能裁剪项目中的固定版本，包含第三方许可文本；原项目未修改。组件清单及 SHA-256 见 `dist/ocr/manifest.json`。

开发预览：运行 `npm run serve` 后，打开 [http://127.0.0.1:48721/](http://127.0.0.1:48721/)。该地址仅在运行预览服务的 Mac 上可用。本机测试服务器的 `/fixtures/` 路由仅用于读取测试素材，生产部署中不存在该服务器和路由。项目和部署目录均不含用户素材或已生成的金融截图。

测试：安装 `package.json` 中的开发依赖，设置 `SAMPLE_DIR` 指向含 `1.PNG` 到 `10.PNG` 对应素材的目录，然后运行 `npm run test:samples` 和 `npm run test:browser`。`BROWSER=webkit` 可测 WebKit。测试产物写入项目相邻的 `qa/`，不会打进站点。Chrome 测试使用已安装的 Google Chrome。

下载路径验证：`node tests/downloads.cjs` 使用本地文件模拟 CDN 响应，验证 jsDelivr 默认优先、备用线路、损坏文件拒绝、Pages 回退、旧缓存复用和原始组件兼容路径，各路径实际识别并导出相同结果；这不代替 CDN 上线后的实网下载验证。`BENCHMARK_ONLY=1 node tests/downloads.cjs` 在相同 5 MB/s 总带宽上限下比较旧版和新版的首下载入与导出。重新生成压缩包运行 `node scripts/build-ocr-transport.mjs`，发布时须先上传清单 `cdnRevision` 指定的组件提交。

提前下载与方向验证：`node tests/preload-stitch.cjs`，以及 `BROWSER=webkit node tests/preload-stitch.cjs`。验证无照片预下载、错误重试、缓存状态、5 组横向与竖向 PNG、敏感数字覆盖、上下交换、方向保存和离线识别。测试使用 `?source=origin` 隔离网络波动。组件已准备在独立的 `ocr-assets` 分支，页面发布分支仍为 `gh-pages`；实网下载测试另行记录。

检查页手势验证：`node tests/editor-gestures.cjs`，以及 `BROWSER=webkit node tests/editor-gestures.cjs`。检查整图适配、放大后滑动条、双指拖动、单指框选、取消手势、底部可见性及实际 PNG 导出。Chrome 使用真实触屏事件，WebKit 使用 PointerEvent 验证手势状态和实际鼠标拖动验证滑动条；不代替实体 iPhone 测试。

验证范围和结果随交付附在“验证说明.md”中。桌面 WebKit 通过不代表已在实体 iPhone 上测试相册、主屏幕安装或 iOS 分享面板。
